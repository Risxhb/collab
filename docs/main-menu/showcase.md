# Animated arena showcase

Open `Assets/LastBell/Menu/ShowcaseMainMenu.unity`, the first enabled build scene. It contains every showcase environment in one scene. The original `MainMenu.unity`, arena source scenes, hero selector and playable Run scenes are preserved.

The sequence loops every 75 seconds, switching at 15, 30, 45, 60 and 75 seconds. Each swap now fades the arena through a deep midnight color over 0.55 seconds on each side. There is no building geometry or foreground wipe. The menu renders above the fade and stays interactive. The camera orbits at 1.2 degrees per second (18 degrees during each stage), resetting its framing beneath the fade.

The bottom-right player has **Play**, **Pause** and **Next** buttons plus the current track and playback status. The playlist cycles **mainmenu2 → mainmenu3 → the existing menu song → mainmenu2**, both automatically at song end and through Next. Next while paused selects the next track without starting it; Play resumes the selected track. Track 2 is an exact copy of the supplied `E:/Collab/audio/mainmenu2.wav`, stored as `Menu/MainMenu2.wav` (SHA-256 `c005df32b3b1ab89c1af5e81967efeb68fc8ce3953d7b8ebcb518ad26c97c4d5`). Track 3 retains the existing `MainMenuOpening` resource name, and the original song retains `MainMenuMusic`. Volume still comes from Settings. The persistent music source and manual pause state survive arena changes, hero selection and preparation; existing boss-track crossfades remain intact.

Menu actors reuse the existing models, animation presenters and presentation FX. They perform sustained autonomous choreography without creating a CombatWorld, damage authority or network session. Casts cannot die or finish the showcase. Eight player models and four bosses are cached during startup; each change switches the active cast and resets pooled FX and trails without instantiating models or graphs. Navigation stops the showcase, and scene unload releases the complete cache, including inactive actors. The rotation clock begins after scene preparation.

## Building and checking

- Windows: `LastBell.Menu.EditorTools.MenuShowcaseBuild.BuildWindows`; default output is `E:/Collab/builds/menu-showcase-current/LastBell.exe`, overridable with `LASTBELL_SHOWCASE_OUTPUT`.
- Browser: `LastBell.Menu.EditorTools.WebDemoBuild.Build`; output may be set with `LASTBELL_WEB_OUTPUT`. Includes showcase menu, hero selection and five playable maps. Build in a separate browser project to preserve the primary project's target.
- Rendered acceptance: launch a development player with `-lastbellShowcaseTest -lastbellOut <evidence-folder>`. Exercises two actual 75-second rotations, all casts, fade coverage/input, faster orbit, music controls/pause continuity, complete playlist cycling, bounded resources and selection/return cleanup. Each menu clip is sought near its end to check automatic advancement and wraparound.
- Existing navigation/hero/test-map/run regression: `-lastbellFlowStage 8 -lastbellOut <evidence-folder>`.
- Source arenas are never regenerated by these build commands. `Prepare Showcase Scene` only creates a missing derived scene and refuses to overwrite existing showcase work.
